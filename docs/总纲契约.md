## ② 系统架构与 AI 能力

```
React 前端 ──HTTP──▶ NestJS 业务后端 ──HTTPS(出站)──▶ 大模型 API（豆包/通义千问）
                              └─ ai 模块（内部模块：调 LLM + 提示词 + 进程内缓存）
```

AI 模块原则：

① 后端内部模块，不独立部署，不引入 Redis；进程内 Map 缓存（key = hash(text + count)，TTL 1 小时）。
② 只封装「调 LLM API + 提示词 + 结果缓存」，不承载业务判断（是否入库、如何入标签由 cards Service 决定）。
③ 输出为结构化 JSON，便于业务端解析。
④ LLM 调用超时 10s，失败返回 503，不阻塞非 AI 主流程。

AI 能力清单：

| 方法 | 功能 | 输入 | 输出 |
| --- | --- | --- | --- |
| `aiService.generateCards()` | 从文本生成闪卡 | `{ text, count? }` | `{ cards: [{front, back}] }` |
| `aiService.formatMarkdown()` | 智能格式化 Markdown | `{ content }` | `{ formatted }` |

## ④ 分层调用链（唯一合法链路）

后端（单向依赖，禁止反向）：

```
Module → Controller → Service → Repository → Prisma Client
```

- 横切：common/filters（全局异常）、common/interceptors（统一响应）、auth/guards（JWT 守卫）
- ai 模块：只允许被 Service 依赖，禁止被 Controller 直接依赖

前端（单向依赖，禁止反向）：

```
Router → Pages → Components → Store(Zustand) → Services(Axios) → Types
```

- 组件禁止直接调用接口；接口请求全部封装在 Services 层

## ⑦ 数据对象分层铁律

① 请求入参：Controller 用 DTO（class-validator 校验），Service 只接收 DTO 或原始类型参数

② Prisma Entity 不得跨模块传递；敏感字段（passwordHash）在任何响应中出现即违规

③ 前端 types/ 全部内容只能从总纲会话复制，文件头标注来源（如 `// 本文件来自总纲契约 v2.0，禁止本地修改`）；需要新类型向总纲申请，禁止本地新建与总纲同名的类型

④ 前后端同名类型（Card、Tag、User）逐字段一致，联调时对照检查

## ⑨ 全局禁止项

**分层越界**
① 禁止跨层调用（Controller 碰库、Service 碰 Prisma、组件碰 Axios）
② 禁止反向依赖（Repository import Service、下层 import 上层）
③ 禁止在 A 会话里写 B 模块/B 会话职责的代码

**数据对象**
④ 禁止 passwordHash 等敏感字段出现在任何响应中
⑤ 禁止本地新建与总纲契约同名的类型定义
⑥ 禁止修改接口契约（方法名、参数名、返回类型）

**代码质量**
⑦ 禁止使用 any（含 `ApiResponse<T = any>`，统一写 `T = unknown`）；所有变量、方法标注完整类型
⑧ 禁止吞异常（catch 后不抛不记）；异步一律 async/await
⑨ 关键逻辑加单行注释，不写冗余注释

**工程纪律**
⑩ 禁止引入技术栈清单之外的依赖
⑪ 禁止自由优化、重构指定之外的代码
⑫ 禁止全量重写已有文件，只做增量新增；提示词与输出中禁止使用省略号或「其余同上」
⑬ 不确定的地方标注 TODO，不要自己编造

## ⑩ 统一约定

① 统一响应体：`{ code: number, data: T, message: string }`，成功 code=200、message="success"，由全局拦截器封装，Controller 直接返回业务数据

② 异常策略：业务错误抛 HttpException（带明确 message），由全局异常过滤器统一转成 `{ code, data: null, message }`；禁止在 Service 里 try-catch 后吞掉

③ 事务边界：在 Repository 层（多表写操作封装为 Repository 内一个事务方法，如复习提交同时更新 Card + 写 ReviewLog）

④ 依赖注入：Nest 构造器注入；前端 Store 直接 import Services 的单例函数

⑤ 前端持久化：token 存 localStorage，请求拦截器统一附带 `Authorization: Bearer`

⑥ mock 契约：mock 与接口契约是同一个交付物；开发阶段 request.ts 的 mock 开关为 true，联调一键切 false

⑦ 分页：API 层用 page/size（默认 page=1, size=20），Service 内换算为 `skip=(page-1)*size` / `limit=size` 传给 Repository

⑧ LLM 调用：超时 10s，失败抛 503，不阻塞非 AI 主流程；缓存 key=hash(text+count)，TTL 1 小时

⑨ 更新接口：一律用 **PATCH**（部分更新语义），不用 PUT

⑩ 简化 SM-2 算法：实现为纯函数，是全项目唯一强制单测点（测试矩阵见 ⑬）

⑪ 分层校验：dependency-cruiser 把分层规则写成依赖图（Controller 禁依赖 Prisma/Repository、Service 禁依赖 Prisma、组件禁依赖 axios、禁反向依赖），配 pre-commit 自动拦截

⑫ 提交钩子：husky + lint-staged，每次提交自动跑 `tsc --noEmit` + `eslint --fix` + `depcruise`，任一失败则提交被拦截

⑬ 再锚定：长会话每 20-30 轮（或每完成一个模块）重贴一次全局规范 + 当前模块接口契约，并声明「以上规范重新生效」；发现输出风格漂移立刻再锚定

## ⑪ 本轮允许新增的依赖（白名单）

技术栈表之外，仅允许：@nestjs/swagger（已定引入）、json-server、dependency-cruiser、husky、lint-staged、jest 相关类型包。其余一律禁止。

## ⑫ 数据模型（Prisma Schema，v2）

```prisma
model User {
  id           Int         @id @default(autoincrement())
  username     String      @unique
  passwordHash String
  email        String?
  createdAt    DateTime    @default(now())
  cards        Card[]
  tags         Tag[]
  reviewLogs   ReviewLog[]
}

model Tag {
  id     Int    @id @default(autoincrement())
  userId Int
  name   String
  color  String
  user   User   @relation(fields: [userId], references: [id])
  cards  Card[] @relation("CardTags")

  @@unique([userId, name])
}

model Card {
  id           Int         @id @default(autoincrement())
  userId       Int
  front        String
  back         String
  nextReviewAt DateTime
  reviewCount  Int         @default(0)
  interval     Int         @default(1)
  easeFactor   Float       @default(2.5)
  createdAt    DateTime    @default(now())
  updatedAt    DateTime    @updatedAt
  user         User        @relation(fields: [userId], references: [id])
  tags         Tag[]       @relation("CardTags")
  reviewLogs   ReviewLog[]

  @@index([userId, nextReviewAt])
}

model ReviewLog {
  id         Int      @id @default(autoincrement())
  cardId     Int
  userId     Int
  feedback   String
  durationMs Int?
  reviewedAt DateTime @default(now())
  card       Card     @relation(fields: [cardId], references: [id])
  user       User     @relation(fields: [userId], references: [id])

  @@index([userId, reviewedAt])
}
```

## ⑬ 简化 SM-2 算法 + 单测

三态简化版（forget / fuzzy / remember），非完整 SM-2。核心参数：`interval`（间隔天）、`easeFactor`（难度系数，初始 2.5，下限 1.3）、`feedback`。

**新卡规则（reviewCount === 0）：**

① 记住：`interval = 6`，`easeFactor` 不变
② 模糊：`interval = 1`
③ 忘记：`interval = 1`，`easeFactor -= 0.2`

**非新卡规则：**

① 记住：`interval = ceil(interval × easeFactor)`，`easeFactor += 0.1`
② 模糊：`interval = ceil(interval × 1.2)`，`easeFactor` 不变
③ 忘记：`interval = 1`，`easeFactor = max(easeFactor - 0.2, 1.3)`

**统一收尾：** `nextReviewAt = now + interval 天`，`reviewCount += 1`，写入 ReviewLog（含 durationMs）。

**工程要求：** 实现为纯函数（`spaced-repetition.util.ts`），无 IO、无副作用；必须有单元测试覆盖 6 条路径 + easeFactor 下限边界：

① 新卡 + remember → interval=6，EF 不变
② 新卡 + fuzzy → interval=1
③ 新卡 + forget → interval=1，EF-0.2
④ 老卡 + remember → interval=ceil(interval×EF)，EF+0.1
⑤ 老卡 + fuzzy → interval=ceil(interval×1.2)
⑥ 老卡 + forget → interval=1，EF=max(EF-0.2, 1.3)

> AI 动态调度明确「不做」（效果不可控、不可解释；未来若需先补齐调度数据闭环再立项）。
